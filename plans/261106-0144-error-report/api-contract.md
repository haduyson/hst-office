# HST Office error reports: API contract (v1)

Status: agreed between the HST Office client and system.hasontech.vn for 1.0.0-beta.5. Owner decision 2026-11-06.

## Purpose

A user can send an error report from HST Office: Trợ giúp → "Báo lỗi cho HASON TECH…". After an abnormal exit,
the next start offers to send a crash report. Nothing is sent without the user's explicit click. A report never contains
document content or file names. Reports appear on system.hasontech.vn under menu "HST Office" → "Báo cáo lỗi".

## Endpoint

`POST https://system.hasontech.vn/hst-office/api/error-reports`

- `Content-Type: application/json; charset=utf-8`; body is at most 262,144 bytes (256 KiB).
- No authentication, no cookies. The server must not store the client IP. It may use the IP transiently for rate limiting:
  at most 10 reports per IP per hour, then 429.
- The client sends at most one request per report, with a 15-second total deadline. A retry reuses the same `reportId`.
  The server treats a repeated `reportId` as idempotent and returns the original ticket with 200.

## Request body

```json
{
  "schemaVersion": 1,
  "reportId": "uuid v4, generated by the client",
  "kind": "user | crash",
  "createdAt": "YYYY-MM-DDTHH:MM:SSZ (client clock, UTC)",
  "product": {"version": "1.0.2", "build": "10000"},
  "os": {"family": "windows | macos | linux", "version": "free text ≤ 120", "arch": "x86_64 | arm64"},
  "locale": "vi-VN",
  "app": "writer | calc | impress | draw | math | base | start | unknown",
  "appName": "HST Writer | HST Sheets | HST Slides | HST Draw | HST Math | HST Base | HST PDF | Trang bắt đầu | Không rõ",
  "description": "user text, ≤ 5000 chars; required for kind=user, optional for kind=crash",
  "contactEmail": "optional, ≤ 254 chars, syntactically valid if present",
  "diagnostics": {
    "systemInfo": "optional text ≤ 16 KiB: what Help → About → Copy version info gives, plus VCL backend, UI scale, renderer",
    "log": "optional text ≤ 192 KiB: HST's own recent log lines, already filtered on the client",
    "crash": "optional text ≤ 16 KiB: for kind=crash, what the client knows about the previous abnormal exit"
  }
}
```

Unknown fields are ignored. `product.engine` (the engine version, e.g. `"26.8.1.1"`) is optional: clients up to
1.0.1 sent it; from 1.0.2 the client leaves it out (users see and send the HST Office version only) and the
engine follows from `product.version` ([docs/BUILD_MATRIX.md](../../docs/BUILD_MATRIX.md#phiên-bản-lõi-theo-bản-phát-hành)).
`app` is a stable machine key (the engine's module names; HST PDF is sent as `unknown`); from 1.0.2 the client
adds `appName`, the product name users see (optional, ignored by older servers). Admin views should show
`appName` or map the key (`calc` = HST Sheets, `impress` = HST Slides, ...), never the raw key.
`diagnostics` and each of its fields are optional. The user chooses whether to attach them
(off by default) and sees exactly what will be sent before sending.

## Responses

| Status | Body | Meaning |
|---|---|---|
| 201 | `{"ticket": "HSTO-000123"}` | Stored. The client shows the ticket number to the user. |
| 200 | `{"ticket": "HSTO-000123"}` | Same `reportId` already stored. |
| 400 | `{"error": "invalid"}` | Schema or size violation of a field. |
| 413 | — | Body too large. |
| 429 | — | Rate limited. The client tells the user to try later or use email. |
| 5xx / network | — | The client offers the email fallback (lienhe@hasontech.vn) with the report text prefilled. |

The server never echoes stored content in errors.

## Server interpretation (live server, 2026-11-06)

How system.hasontech.vn reads this contract; the client and its test fake server follow the same rules.

- Required: `schemaVersion` = 1, `reportId` (UUID v4), `kind`, `createdAt` (`YYYY-MM-DDTHH:MM:SSZ`), `product.version`
  (at most 80 characters), `os.family`, `app` (always sent; `unknown` when not known), and `description` when
  `kind` = `user`. Everything else is optional; `null` is treated as absent.
- Limits named in characters count characters. `systemInfo` (16 KiB), `log` (192 KiB) and `crash` (16 KiB) count
  UTF-8 bytes. The client truncates to stay under them and marks the cut (`[… đã cắt bớt …]`).
- The server drops control characters except tab and LF, turns CRLF into LF, and replaces bidi controls and invisible
  characters with U+FFFD; it does not reject for them. The client sanitises the same way, so the preview equals what is
  stored.
- A `contactEmail` containing any of `<` `>` `"` `'` `` ` `` is answered with 400; the dialog refuses it before sending.
- 413 when the body exceeds 256 KiB. 429 above 10 reports per IP per hour or 500 per hour in total; the client then
  offers the e-mail fallback.
- Tickets are `HSTO-` plus 6 digits (11 characters, e.g. `{"ticket": "HSTO-000001"}`), starting at `HSTO-000001`
  (owner change, 2026-11-06); a repeated `reportId` returns 200 with the original ticket. The client shows the ticket string
  the server returns ("Đã gửi. Mã báo cáo: HSTO-000123"), accepting any non-empty printable string of at most 32
  characters.

## Admin page (system.hasontech.vn)

Menu "HST Office" → **"Báo cáo lỗi"**.

- List view: ticket, received time (server time, Asia/Saigon), kind (Người dùng / Sự cố), status, version, OS, app,
  the first line of the description, and handled time. Filters by status, kind, version and OS; search; newest first.
- Statuses: **Mới** (default), **Đang xử lý**, **Đã xử lý**, **Bỏ qua** (duplicate or not a bug). Changing the status
  records who changed it and when; "Đã xử lý" sets the handled time. An internal note field is stored.
- Clicking a row opens a popup with every field: description, contact email, system info, log and crash text in
  monospace with copy buttons, client and server times, `reportId`, the status history and the note.
- Retention: reports older than 180 days are deleted, unless their status is Mới or Đang xử lý.
- Access is admin-only, like the other HST Office pages.
