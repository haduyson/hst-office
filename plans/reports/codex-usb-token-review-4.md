## Major findings

### R4-M1. Quoted internal parameters bind the new store to the old cert/key databases

**Location:** `extensions/hst-vietnamese-tools/python/hst_office/usb_token_store.py:80`, `:85` and `:96`; acceptance of parameters without interpreting their binding at `usb_token_nss.py:43`. This is a defect in the new migration path, not in filename escaping.

The implementation copies the entire internal-module record verbatim and assumes NSS will override its original `configdir`. That holds for the ordinary **unquoted** `parameters=` line generated by certutil. It does not hold for a valid **double-quoted** parameter block:

```text
library=
name=NSS Internal PKCS #11 Module
parameters="configdir='sql:/absolute/old-profile' certPrefix='' keyPrefix='' secmod='secmod.db' flags= ..."
NSS=Flags=internal,critical ...
```

The ellipses above abbreviate unchanged fields; the reproduction retains the complete original parameter and NSS/slot configuration. NSS deliberately treats a quoted parameter block as an override of application-supplied parameters. Its [module-store reader](https://raw.githubusercontent.com/nss-dev/nss/master/lib/util/utilmod.c) documents and implements this distinction using `skipParams`. Preserving the text therefore preserves the binding to the **old** SQL files.

**Reproduced in both modes with real NSS, then independently through actual HST:** initialize a source SQL store, add Builtin Roots and another vendor, quote only the internal parameter value, and invoke the new private-store flow. The source is valid and loads before migration. Setup returns `added`, persists the new CertDir, and displays the private-store/preservation success message. The source is byte-identical immediately after setup.

After a complete HST restart and PDF export:

- `NSSPath` reports the new `Library/Application Support/HST Office/nssdb` directory.
- `/proc/<soffice-pid>/fd` shows **the old profile's `cert9.db` and `key4.db` open**, not files in the new store.
- Neither SQL file is created in the new directory. Repeating setup continues to ask for a restart indefinitely.
- After HST exits, a real `certutil -A -d sql:<new-store>` import writes a disposable sentinel certificate into the **old** store. Independent listing of the old store finds it. Both old SQL-file hashes change while the old `pkcs11.txt` hash remains identical.

Example from the modutil HST reproduction: old `cert9.db` SHA-256 changes from `e6e6ef70e28faeca5218504070dd14f8edf72b52131291523906a23a9c8ebfe0` to `0721a9e5e91be2ca7ecce8d83b31afd73ae8113864fb1a7e84f8a4211de6d196`. This comparison is within one fixture: the import targets the new directory but changes the old directory. This is not a claim that setup itself rewrites the old SQL files.

**Impact:** the promised separate store is not actually separate, the original remains a live writable certificate/key database, and removing or making it unavailable can break the supposedly migrated store. The implementation report's unconditional claim that core creates new SQL files despite the copied `configdir` is false for supported quoted parameters.

**Required fix:** handle the internal database binding explicitly in the new copy while preserving its intended flags and slot policy, or refuse unsupported pinned parameter configurations before selecting a new store, with an actionable Vietnamese message. Do not globally replace strings in arbitrary module records. Add native and real-core regressions for quoted and unquoted internal parameters; assert which SQL paths core opens and that an import addressed to the new store cannot change the old store. Existing tests verify byte prefixes and ordinary certutil records, so they miss this semantic difference.

Evidence: `probes.py`, `probes.log`, `probes/results.json` (both `*-quoted-internal` cases); `core-probes.py`, `core-probes.log`, `/tmp/usb-review-4-runtime/core-probes/results.json` (both modes). The direct probes also reproduce this with source directory mode `0500` and module-file mode `0400`.

### R4-M2. CertDir cannot switch a store pinned by MOZILLA_CERTIFICATE_FOLDER

**Location:** `extensions/hst-vietnamese-tools/python/hst_office/usb_token.py:21`–`:22`, `:33`–`:40`, and the migration decision at `usb_token_store.py:114`–`:116`.

The new flow always treats writing CertDir plus restarting as sufficient to switch core. Core gives the nonempty `MOZILLA_CERTIFICATE_FOLDER` environment variable priority over CertDir. That precedence is visible in the [core selector](https://raw.githubusercontent.com/LibreOffice/core/master/xmlsecurity/source/xmlsec/nss/nssinitializer.cxx) and confirmed in this installed HST. The new unconditional preference for any marked configured store then masks the mismatch on every subsequent invocation.

**Reproduced in both modes, through two actual HST policies:**

1. Start HST with `MOZILLA_CERTIFICATE_FOLDER` pointing to a valid existing profile with roots/vendor records and no new token registration.
2. Trigger private-store migration: first with the forced Darwin policy; separately on ordinary Linux with a real open reader on `pkcs11.txt` making the lease unavailable. The Linux reproduction uses **no Darwin/platform override**.
3. Setup registers SoftHSM only in the new store, saves its path to CertDir, says HST now uses its own store, and requests restart.
4. Fully restart with the same environment. `NSSPath` and the open SQL descriptors still select the **old** profile. The new store has no `cert9.db`/`key4.db`; its token registration is not in the database core loaded.
5. Repeat setup. Because the configured directory has the HST marker, setup reads that unused store and reports `Đã đăng ký từ trước`, again requesting a restart. Further restarts cannot fix the precedence.

All **4/4 policy/mode combinations** reproduce the failure. The old profile remains byte-identical; the defect is persistent registration into a store core never selects. This is a new variant of round-1 M2, even though its original absolute/`sql:`/missing/tilde regression cases still pass.

**Required fix:** distinguish a transient cached path from a persistent environment override. Before switching, either fail safely with Vietnamese instructions explaining the override or implement a supported switch that actually governs core selection. Do not silently unset a user/admin override in one process and claim restart will preserve it. Limit the marked-CertDir preference to a valid pending switch, and verify effective selection after restart. Add both forced-Darwin and real Linux lease-unavailable cases with an inherited environment override.

Evidence: `core-probes.py`, `core-probes.log`, `/tmp/usb-review-4-runtime/core-probes/results.json`; `linux-lease-core-probes.py`, `linux-lease-core-probes.log`, `/tmp/usb-review-4-runtime/linux-lease-core-probes/results.json`.
